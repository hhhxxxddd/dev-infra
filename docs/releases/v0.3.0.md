# dev-infra v0.3.0

## 简体中文

- 首次公开发行，提供开箱即用的 MySQL、PostgreSQL、Redis、Kafka、RustFS 和 Mailpit，通过 Windows/WSL 共用的 Docker Compose 后端管理连接、生命周期与数据。
- 精简命令，裸命令和 `help` 显示帮助，`list` 查看中间件，`upgrade` 升级中间件，`self upgrade` 更新工具；`-v` 查看版本。默认中文，用户配置可切换英文。
- `check --updates` 和 `upgrade` 共用升级计划，校验兼容范围、目标版本与备份策略，固定镜像摘要并在切换前拉取全部镜像；拒绝不兼容旧卷和已知降级。
- 数据归属以当前实例的 Docker 标签为准。`data prune --yes` 只清理有归属证明且没有当前配置或容器引用的旧卷，删除前再次核验；`data reset --yes` 显式重置所选当前数据。
- 升级日志保留失败阶段、已完成步骤、逐服务进度与已完成备份；只读 `check` 给出日志和重试建议，不自动降级或回滚数据库。配置和状态按数据解析，未知格式或损坏记录明确报错。原始 Compose 的变更与未知命令也使用实例操作锁，已知只读命令不创建实例文件。
- Windows/WSL 均支持已有原生 Python 3.14，可共享独立的基础解释器。安装、更新与卸载不安装、升级或删除外部 Python；部署保留本机配置、版本覆盖、归属记录、备份与数据卷，不重启中间件。
- Git 安装验证官方来源并只快进更新；发行包安装校验官方稳定 Release；Scoop 通过 hxd-box 安装和更新。`self update` 仅重新部署当前代码。
- 固定 CLI JSON schema_version=1、错误码与退出码，保持机器字段独立于显示语言，Windows 转发保留 JSON 和退出码，诊断隐藏已知凭据和 SQL。
- 提供独立完整 ZIP、SHA256SUMS 和 Scoop 清单，包含两端入口、安装脚本、Compose、配置、初始化脚本、双语文档和 MIT 许可。发行包记录来源 commit 与逐文件校验值；正式构建要求干净源码与对应 tag。
- 新增 Windows/Ubuntu CI、文档/TOML 校验及解压包原生入口验证，两平台产物逐字节相同才能发布；已公开的版本附件不覆盖。

Scoop 自动准备 PowerShell。安装前需准备两端原生 Python 3.14，以及 WSL 中的 rsync、flock、Docker 和 Compose v2。工具更新保留实例数据；跨兼容范围的中间件升级须按迁移文档执行。

## English

- First public release of ready-to-use MySQL, PostgreSQL, Redis, Kafka, RustFS and Mailpit, with connection, lifecycle and data management through one Docker Compose backend shared by Windows and WSL.
- Short commands: running without arguments or with `help` shows help, `list` shows middleware, `upgrade` updates middleware, `self upgrade` updates the controller, and `-v` shows its version. Chinese is the default; user configuration can select English.
- `check --updates` and `upgrade` share a plan covering compatibility scopes, target versions and backup preferences. Image digests are pinned and all images are pulled before cutover; incompatible old volumes and known downgrades are rejected.
- Volume ownership requires Docker labels matching the current instance. `data prune --yes` only removes proven owned old volumes without current declarations or container references and rechecks before deletion; `data reset --yes` explicitly resets selected current data.
- Upgrade journals retain failed stages, completed steps, per-service progress and completed backups. Read-only `check` suggests log and retry commands without automatically downgrading or rolling back databases. Configuration and state are parsed as data; unsupported formats and damaged records fail clearly. Raw Compose mutations and unknown commands also use the instance lock; known read-only commands do not create instance files.
- Existing native Python 3.14 is supported on Windows and WSL, including a shared independently managed base interpreter. Installation, updates and removal never install, upgrade or delete external Python. Deployment retains native settings, image overrides, ownership records, backups and volumes without restarting middleware.
- Git installation verifies the official source and only fast-forwards; package installation verifies the official stable Release; Scoop installation and updates use hxd-box. `self update` only redeploys current code.
- CLI JSON schema_version=1, error codes and exit codes have documented contracts. Machine fields are independent of display language, Windows forwarding preserves JSON and exit codes, and diagnostics redact known credentials and SQL.
- Complete standalone ZIP, SHA256SUMS and Scoop manifests include both platform entrypoints, installers, Compose, configuration, initialization scripts, bilingual documentation and the MIT license. Packages record the source commit and per-file checksums; official builds require clean sources at the matching tag.
- Windows/Ubuntu CI validates documentation, TOML and native entrypoints from extracted packages. Platform artifacts must have identical bytes before publication; published version assets are never overwritten.

Scoop prepares PowerShell automatically. Before installation, provide native Python 3.14 on both platforms and rsync, flock, Docker and Compose v2 in WSL. Controller updates retain instance data; middleware upgrades across compatibility scopes require the documented migration procedure.
